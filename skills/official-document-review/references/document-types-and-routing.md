# 文种与行文检查

## 通知

适用于发布、传达要求下级执行或有关单位周知、执行的事项，以及批转、转发公文。不能仅凭“需要告知”选择通知，还要核对受文对象、隶属关系和职权范围。

## 通报

适用于表彰先进、批评错误、传达重要精神或者告知重要情况。审核时核对事实依据和通报目的；不得把一般部署、普通周知机械包装成通报，也不得根据未经确认的材料作出表彰、批评或责任结论。

重点检查事实和数据是否核实，表彰、批评、责任认定和处理意见是否经过有权机关确认，落实要求是否属于发文机关职权，跨部门事项是否已经协商。核心目的只是部署执行或一般周知时，重新判断是否应使用通知。

## 报告

适用于向上级汇报工作、反映情况或回复询问。报告不得夹带需要上级指示、批准的事项。

## 请示

适用于向上级请求指示、批准。请示应一文一事。下级请示需要以本机关名义继续请示时，应提出倾向性意见，不得原文转报。

## 批复

适用于答复下级机关请示事项。审核时核对来文及上下级关系，确认答复内容与原请示对应，并将答复意见是否经过有权机关决定列为内部确认事项。

逐项比对原请示和批复：来文机关、标题、发文字号、核心请求、答复意见及附加要求。检查是否遗漏请求、答非所请、扩大决定范围，或写入未经确认的同意、否决和条件。涉及其他部门职权时核实协商情况，并核实适用办理期限，不自行设定全国统一期限。

## 函

适用于不相隶属机关之间商洽工作、询问和答复问题、请求批准和答复审批事项。审核时必须核实机关关系；存在上下级关系时，应结合行文目的重新判断请示、批复等文种。

核实核心目的是否属于法定场景，事项是否在职权范围内，复函是否针对来函逐项回应，承诺和答复是否已经确认。将函文种与GB/T 9704中的信函格式分别审核，不得无条件绑定。

## 行文关系

- 根据隶属关系和职权范围判断行文方向。
- 一般不得越级；特殊情况越级时同时抄送被越过机关。
- 上行文原则上主送一个上级，不抄送下级。
- 涉及多个部门职权的事项需要核实协商或会签情况。
- 判断必须依赖真实组织关系，不得只根据机关名称猜测。

详细依据以相对于本 Skill 目录的 `../../standards/document-types/` 和 `../../standards/writing-rules/routing.yaml` 中通过准入门禁的规则为准。
