# 审核工作流

## 1. 任务分流

先判断文本属于法定公文、一般机关事务文稿还是尚无法确定。只有法定公文才完整适用党政机关公文规则；一般材料不得机械套用全部公文版式。

## 2. 背景充分性

将审核所需信息分为三类：

- 已知事实：用户明确提供或文稿中可直接确认；
- 待核实事实：文号、数据、政策名称、时间、单位名称等缺少依据；
- 必须补充的上下文：隶属关系、职权范围、授权、协商会签情况等。

不得把推测写成事实。背景不足时仍可审核语言和内部一致性，但对文种、行文关系及职权问题保留结论。

## 3. 规则选择

依次检查：

1. 来源覆盖和规则状态；
2. 文种规则；
3. 行文规则；
4. 起草与审核规则；
5. 公文组成和版式规则；
6. 标点与数字规则。

同一问题有多条依据时，引用最直接的规则；必要时再补充上位规则。资料性附录只能作为说明，不能表述为强制要求。

## 4. 问题分级

- `阻断`：可能导致文种、行文对象、职权、请示事项或关键事实根本错误。
- `重要`：违反明确规范，影响办理、理解或正式印发。
- `一般`：局部格式、标点、数字或表达问题。
- `提示`：需要内部确认或属于非强制优化建议。

## 5. 修改建议

建议应最小化修改并保持原意。涉及事实、政策、数字和机关权限时，只指出待核实内容，不代替用户编造补齐。用户要求直接修改文稿时，先处理可确定问题，再把无法确定处明确标为待确认。

## 6. 结束检查

确认审核报告：

- 没有把建议性规则写成强制规则；
- 没有隐去待核实事实；
- 没有声称代替内部审批签发；
- 每项规范问题均能追溯到规则编号或明确标注为表达建议。
