# 规范来源与外部材料导入说明

本目录登记 Standards 使用的权威来源。项目不会依据模型记忆补写规范内容；候选材料必须取得原文并完成核验后，才能转化为正式规则。

当前来源登记见 [source-index.yaml](source-index.yaml)。用户提供的原始材料保存在 [originals/](originals/) 中，并在再分发许可明确前由 Git 忽略。

## 可选补充材料

在核心材料完成后，可以补充：

- 你所在地区由党委、政府或办公厅公开发布的现行公文处理制度；
- 公开发布的通知、报告、请示实例链接；
- 经确认可以使用的单位格式样张或空白模板；
- 已脱敏且获授权用于项目建设的内部写作要求。

地方制度或单位制度不能默认推广到全国。导入时必须标记适用地区、适用单位和与上位规范的关系。

## 请如何提供

每次最好只提供一份材料，并附：

1. 正式名称；
2. 文件号或标准号；
3. 原始权威网址；
4. PDF、网页导出文件或完整文本；
5. 获取日期；
6. 你是否知道其现行状态；
7. 是否允许把原文提交到公开仓库。

如果不确定第 6、7 项，直接标注“不确定”，项目将保持待核验状态。

推荐文件名：

```text
SOURCE-001-党政机关公文处理工作条例.pdf
SOURCE-002-GBT-9704-2012-党政机关公文格式.pdf
SOURCE-003-GBT-15834-2011-标点符号用法.pdf
SOURCE-004-GBT-15835-2011-出版物上数字用法.pdf
```

文件名只是项目内部约定，不改变文件的正式名称。

## 不要提供的材料

- 涉密文件或带有密级标志的材料；
- 内部未公开且未获授权的制度；
- 含个人隐私、工作秘密、账号或联系方式的数据；
- 来源不明的“公文写作大全”、网盘合集或培训课件；
- 已废止但未明确标注历史用途的旧制度；
- 付费取得但无权复制给项目或公开分发的资料。

## 版权处理

原文可供在线阅读，不当然意味着可以纳入开源仓库重新分发。

对于许可状态不明确的材料：

- 可以由用户提供给当前工作过程用于核对；
- 仓库只保存来源元数据、条款定位和原创结构化规则；
- 不提交完整 PDF、扫描件或大段原文；
- 引用保持必要限度，并链接到权威来源。

## 导入后的处理

收到材料后，项目将依次：

1. 核对文件身份和完整性；
2. 登记来源元数据；
3. 标记效力与许可状态；
4. 按文种、行文、起草、审核和格式等主题提取候选规则；
5. 为每条规则记录精确出处；
6. 请用户复核容易产生歧义或依赖机关背景的内容；
7. 通过后再用于 Drafting 和 Review。
