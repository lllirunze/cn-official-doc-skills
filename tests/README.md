# 测试体系

v0.1.0 先使用结构化行为样例验证规则和 Skills，不把固定措辞当作通过条件。

每个样例至少包含：

- 唯一编号和被测能力；
- 关联规则编号；
- 用户输入及必要背景；
- 预期结论、严重程度和必须识别的问题；
- 不允许出现的行为；
- 判断方式和是否需要人工确认。

`fixtures/core-cases.yaml` 保存39个高风险样例，覆盖 `coverage.yaml` 确定的全部62条首版核心规则。后续自动化测试应验证可观察行为，例如是否识别一文多事、是否拒绝编造文号，而不是匹配模型输出的固定句子。

## 状态

- `draft`：样例已建立，尚未复核；
- `source_checked`：与规则和来源定位一致；
- `human_approved`：项目维护者已经确认；
- `automated`：已经纳入可重复执行的自动化测试。
